# API маршрута одного ОКС

Сначала импорт должен пройти `POST /api/v1/imports/{id}/geometry` и получить
`geometry_status=READY`.

`POST /api/v1/imports/{id}/routes/single`

```json
{"targetOrdinal": 0, "diameter": 200}
```

`targetOrdinal` — ordinal объекта `oks_connection_point`. `diameter` — один из
ДУ таблицы 1 приложения; здесь он нужен для габарита и отступов и ещё не
подбирается по расходу автоматически (расход и итоговый ДУ участка считает
сборка общей сети, см. `network-api.md`).

При успехе ответ имеет `status=ROUTED`, `connected=true`, `tiePoint`, общую длину,
координаты маршрута в EPSG:32637 и EPSG:4326, углы поворотов, сегменты, интервалы
base/special и диагностические счётчики поиска. Если допустимого пути в построенном
графе нет, сначала выполняется расширенный поиск (шире коридор, до 30 000 вершин,
64 соседа, до 1200 кандидатов присоединения). Ответ `status=NO_ROUTE_FOUND`
даётся только с доказательством: область, где может лежать ось трубы этого ДУ
(плоскость минус зоны габаритов всех препятствий, каждая зона слегка занижена),
в окне 800×800 м вокруг цели замкнута, не выходит за окно и не касается
существующей сети — тогда маршрута не существует при любом графе поиска. Если доказать не удалось или
поиск остановлен пределом времени/размера, ответ — `status=NO_ROUTE_FOUND`,
`reason=SEARCH_INCOMPLETE`, `searchIncomplete=true`: отсутствие маршрута не доказано. Ошибочный ordinal/ДУ даёт 400; превышение операционного предела — 422.

Метод не принимает координаты маршрута. Он не объединяет потребителей, не создаёт
камеры, не считает расходы, не подбирает ДУ, не считает стоимость и не формирует
итоговый GeoJSON.

## Область графа

Пространственно обоснованная область графа — коридор от цели до ближайшей
точки собранной существующей сети. Полуширина равна 25% прямой дистанции, но
не менее 100 м и не более 1 км. Ограничения вне коридора всё равно участвуют
в проверке каждого ребра; область влияет только на набор вершин для обхода
препятствий. Параметр не передаётся пользователем и не зависит от координат
конкретного импорта.

## Последняя страховка полноты: поиск по сетке

Если обычный граф и расширенный поиск ничего не нашли, а замкнутость не доказана, для ограниченного набора целей (расширенный проход)
выполняется независимый от графа видимости поиск по сетке: плоскость режется на ячейки 1 м, ячейка свободна, если ось трубы этого ДУ может
стоять в её центре с запасом полдиагонали ячейки, ход разрешён в 8 направлениях с поворотом не более 90° между шагами, цель — ячейка в 1,5 м от
существующей сети (до 300 000 состояний). Найденный путь превращается в ломаную тем же правилом упрощения и принимается только после проверки
каждого сегмента настоящим движком ограничений и поворотов — неверный путь можно лишь отбросить. Так `SEARCH_INCOMPLETE` остаётся только там,
где проход уже сетки (уже ячейки) или превышен предел состояний. Отключается `-Dlct.gridSearch=false`.
