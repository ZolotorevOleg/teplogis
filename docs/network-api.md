# API общей сети

## POST `/api/v1/imports/{id}/networks/plan`

Тело для всех ОКС:

```json
{}
```

Тело для выбранного подмножества:

```json
{"targetOrdinals":[0,1,2]}
```

Основные поля ответа:

- `status`, `totalTargetCount`, `connectedTargetCount`, `totalLengthM`;
- `targets[]`: ordinal/id, расход, статус, причина, начальный ДУ и рёбра пути;
- `edges[]`: координаты, длина, суммарный расход, ДУ, нижележащие ОКС,
  статус повторной проверки и способы прокладки;
- `nodes[]`: камера, технический узел или точка ОКС, признак существующего
  объекта, число присоединений и ДУ;
- `problems[]`: нарушения итоговой топологии, гидравлики или ограничений.

Ошибки запроса возвращаются с кодом `BAD_NETWORK_REQUEST`. Некорректный JSON —
`BAD_REQUEST`. Отсутствующая подготовка геометрии возвращает 409. Нормальный
расчёт с неподключёнными ОКС возвращает HTTP 200 и статус `PARTIAL` либо
`NO_FEASIBLE_NETWORK`, чтобы причины оставались доступны в теле ответа.

Операционный предел одного запроса — 50 ОКС; тайм-аут или предел сложности
одного маршрута не отменяет результаты остальных.

## Алгоритм сборки

1. Для каждого ОКС по расходу перебираются ДУ таблицы от меньшего к большему.
   Используется первый допустимый маршрут, длина которого не превышает предел ДУ.
2. Совпадающие линии объединяются. Все концы и геометрические пересечения делят
   линии на атомарные рёбра; пересечение становится общим узлом.
3. Сеть проверяется на циклы и степень узла. Разветвление или пересечение
   оформляется `heat_chamber`, не более четырёх линейных присоединений.
4. Расход ребра равен сумме расходов всех нижележащих ОКС. Непрерывные участки
   между изменениями расхода получают минимальный ДУ по пропускной способности
   и длине. ДУ не уменьшается в направлении от ОКС к существующей сети.
5. Узел с неизменным ДУ не сбрасывает счётчик предельной длины. При превышении
   вся непрерывная цепочка повышается до минимально достаточного следующего ДУ.
6. Каждое итоговое ребро повторно проверяется движком ограничений уже с
   рассчитанным ДУ. Границы специальных способов прокладки создают
   `technical_node`.
7. Точка присоединения переносится в существующую камеру в радиусе 10 м только
   если новый подход допустим и суммарное число присоединений не превышает 4;
   иначе в точке присоединения создаётся новая камера.

Ограничение: общая сеть формируется объединением независимо найденных
кратчайших маршрутов; совпадающие участки и пересечения объединяются строго
геометрически, глобальная оптимизация расположения новых общих участков не
выполняется.
