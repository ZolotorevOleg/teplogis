# Геометрическое ядро и API

Сначала POST `/api/v1/imports` загружает исходный файл по входному контракту
(`input-contract.md`). Затем POST `/api/v1/imports/{id}/geometry` выполняет
геометрическую подготовку. Ни один endpoint загрузки не удалён и его формат
ответа не изменён.

## Подготовка

Оригинал хранится без изменений. Сканер читает Features последовательно, переписывает
геометрию во временный JSON, затем пишет стандартный big-endian 2D WKB. Дисковый
буфер позволяет узнать тип геометрии независимо от порядка полей и дописать счётчики
вершин без хранения координат в heap. Временные файлы удаляются и при исключении.
Поддержаны Point, LineString, MultiLineString, Polygon с отверстиями и MultiPolygon.

WKB передаётся PostgreSQL через JDBC `setBinaryStream` с известной длиной.
Сначала проверяется WGS84-геометрия через ST_IsValidDetail, затем выполняется
ST_Transform в EPSG:32637 и повторная проверка. Проверяются пустые, вырожденные,
самопересекающиеся полигоны, отверстия и нечисловые результаты проекции.
Автоматического ST_MakeValid или изменения исходного набора нет.
Несамопростая линия отмечается `simple=false`, но не приравнивается к невалидному
полигону и не отклоняется только из-за пересечения самой себя.

В `input_geometries` сохраняются две геометрии, diameter, flow_tph, restriction_type,
длина линий в метрах, площадь полигонов в м², признаки простоты и выхода за номинальную
область UTM 37N. Площадь в сводке — сумма площадей объектов, без вычитания наложений;
это не площадь объединённой территории. Длина — сумма существующих линий всех типов,
не стоимость и не протяжённость новой сети.

Все записи одного импорта создаются в одной транзакции. Ошибка приводит к rollback,
`geometry_status` остаётся NOT_PREPARED, оригинальный импорт остаётся READY.
Повторная успешная подготовка идемпотентна. `FOR UPDATE NOWAIT` предотвращает
одновременную подготовку одного импорта в нескольких процессах.

## Запросы

| Метод и путь относительно /api/v1/imports/{id}/geometry | Результат |
|---|---|
| POST / | Подготовить геометрию; статус, SRID и статистика |
| GET / | NOT_PREPARED или READY и статистика |
| GET /objects?after=-1&limit=100 | Атрибуты и метрики; пагинация по ordinal |
| GET /nearby?longitude=…&latitude=…&radiusM=… | Ближайшие объекты внутри указанного радиуса |
| GET /relation?first=…&second=… | Расстояние, intersects и first_covers_second |

Пути в таблице с `/` обозначают сам базовый endpoint без завершающего слеша.
`ordinal` — номер Feature с нуля, используется для адресации внутри импорта.
`id_json` — канонический JSON-скаляр исходного ID в текстовом поле, например `1`
или `"1"`; тип ID не теряется. Это не новый идентификатор исходных данных.

Все запросы ограничены UUID импорта. Поиск использует ST_DWithin и GiST индекс
расчётной геометрии; расстояния и сортировка по расстоянию вычисляются в EPSG:32637.
`objectType` необязателен. При равном расстоянии порядок стабилен по ordinal.
`limit` от 1 до 1000; радиус от 0 до 100 000 м — эксплуатационный предел endpoint,
не ограничение маршрута или территории поиска. Ответ nearby содержит до limit объектов.

Ошибки: 400 — некорректные параметры; 404 — импорт или ordinal не найден;
409 — подготовка ещё не выполнена, исходник отсутствует или импорт занят;
422 — невалидная/слишком большая геометрия с путём `$.features[N].geometry`;
503 — ошибка хранилища.

## Ограничения

- Вычислительная геометрия 2D; Z остаётся в оригинале.
- По спецификации расчётная система фиксирована EPSG:32637. Выход за её номинальную
  область отмечается предупреждением, а не сменой CRS и не запретом поиска.
- Один WKB ограничен 1 000 000 000 байт; это запас относительно предела PostgreSQL
  bytea. Файл в целом сохраняет лимит размера входа. Большая отдельная геометрия может
  потребовать значительную память GEOS на стороне БД даже при малом heap Java.
- Временная геометрия занимает диск. Фоновая уборка (`operations.md`) удаляет
  оставшиеся после аварии файлы `geometry-*.json` и `geometry-*.wkb` старше
  настроенного защитного окна.
- Проверки принадлежности точки собственному ОКС, допустимости отступа и
  пересечения, подключений камер и топологии новой сети — в `restriction-api.md`
  и `network-api.md`.

## Источники технических решений

- [PostGIS ST_Transform](https://postgis.net/docs/ST_Transform.html): преобразование координат, не простая смена метки SRID.
- [PostGIS ST_IsValidDetail](https://postgis.net/docs/ST_IsValidDetail.html): диагностика корректности геометрии GEOS.
- [PostGIS ST_DWithin](https://postgis.net/docs/ST_DWithin.html): единицы CRS и использование пространственных индексов.
## Картографическая выдача для веб-интерфейса

`GET /api/v1/imports/{id}/geometry/map?after=-1&limit=1000` возвращает страницу
входных объектов как WGS84 `FeatureCollection`. Дополнительные поля верхнего
уровня `nextAfter` и `hasMore` используются для последовательной загрузки карты.
`limit` должен быть от 1 до 2000. Исходный строковый или числовой тип `id`
сохраняется.
