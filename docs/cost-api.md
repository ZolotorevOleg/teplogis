# API стоимости и вариантов

## `POST /api/v1/imports/{id}/variants/calculate`

Тело необязательно:

```json
{
  "targetOrdinals": [12, 18],
  "maxVariants": 3
}
```

Если `targetOrdinals` отсутствует или пуст, обрабатываются все точки ОКС импорта.
`maxVariants` допускает значения 1–3 и по умолчанию равен 3. Координаты маршрута
клиент не передаёт.

Ответ содержит `mode: "2D"`, общий статус и массив `variants`. Для варианта
возвращаются его идентификатор, профиль построения, `rank`, собранная сеть,
детальная стоимость частей каждого ребра и сводка:

- `networkConstructionCost`;
- `chamberConstructionCost`;
- `existingChamberTieInCount` и `existingChamberTieInCost`;
- `constructionCost`;
- `unconnectedPenalty`;
- `calculatedCost`;
- `newNetworkLength`;
- `score`;
- `unconnectedOksIds` с сохранением типа входного ID.

`RANKED` означает, что все цели каждого возвращённого варианта подключены.
`PARTIAL` означает наличие технически ненайденных подключений и начисленных
штрафов. `NO_VALID_VARIANTS` означает, что все кандидаты нарушили финальную
проверку сети.

## `GET /api/v1/cost-rules`

Возвращает табличные ставки нового строительства, стоимость врезки, формулы
штрафа и score. Справочник предназначен для UI и проверки интеграции.

Ошибочное тело или `maxVariants` вне 1–3 возвращает 400. Несогласованное покрытие
участка ценовыми секциями возвращает 422 вместо частичного расчёта.

## Формулы

Обычная часть участка: `length * table_rate(DN)`. Специальная часть:
`length * table_rate(DN) * Kspecial`. Разбиение и максимальный коэффициент на
перекрытии специальных проходов берутся из движка ограничений (см.
`restriction-api.md`).

`constructionCost` включает новые участки, новые камеры и врезки. Новая камера
стоит 3/5/8/12 млн руб. по диапазону максимального примыкающего ДУ. Каждый новый
линейный участок, заканчивающийся в существующей камере, даёт одну врезку за
5 млн руб.

Штраф ОКС: `100000000 + 500000 * flow_tph`.

`score = 0.7 * (calculatedCost / 25000000) + 0.3 * (newNetworkLength / 100)`.
Меньший `score` получает меньший `rank`.

## Автоматические варианты

Первый профиль использует обычный поиск по всем точкам присоединения. Второй и
третий сначала предпочитают соответственно вторую и третью ближайшую существующую
ветвь `heat_network`. Если предпочтительная ветвь недоступна, поиск автоматически
возвращается ко всем ветвям — профиль поэтому не отключает ОКС, который способен
подключить обычный поиск.

Два результата считаются содержательно разными, когда различается существующая
ветвь присоединения, длина меняется минимум на 25 м или 10%, либо геометрия после
квантования 25 м имеет менее 65% общих рёбер. Эта явная трактовка исключает
небольшое смещение той же трассы отдельным вариантом. Сервис может вернуть
меньше трёх вариантов. Кандидат не ранжируется, если финальная сеть содержит
проблему топологии/гидравлики или ребро со статусом, отличным от `ALLOWED`.
