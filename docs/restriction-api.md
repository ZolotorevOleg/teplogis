# API движка ограничений

`GET /api/v1/restrictions/rules` возвращает ширины из таблицы 1, все правила,
пороговые отступы ОКС. Значения в rulesAtDn200 показаны для новой/существующей сети ДУ200.

`POST /api/v1/imports/{id}/restrictions/check-segment`

```json
{
  "coordinates": [[37.6,55.75],[37.601,55.75]],
  "srid": 4326,
  "diameter": 200,
  "targetOrdinal": null
}
```

coordinates: ровно две позиции XY. srid: 4326 (по умолчанию) либо 32637.
diameter: ДУ из таблицы 1; подбор ДУ не выполняется. targetOrdinal: необязательный
ordinal точки подключения ОКС в этом импорте, совпадающей с концом сегмента.
Направление start → end определяет вход в полигон и финальный подход.

Ответ 200:
- status: ALLOWED / BLOCKED / INDETERMINATE;
- allowed: true / false / null соответственно;
- coordinates, lengthM, pairWidthM: расчётный сегмент в EPSG:32637;
- violations: доказанные нарушения с ordinal, исходным ID в idJson, компонентой,
  кодом и фактическим/требуемым расстоянием или углом;
- unresolved: случаи без однозначного правила; они не дают разрешения;
- exemptions: применённый подход к собственному ОКС;
- specialPassages: каждое пересечение отдельно, необходимые отступы fromM/toM
  вдоль сегмента, коэффициент и угол;
- sections: разбиение на base/special по всем границам, активные passageIndexes,
  максимальный coefficient. Это требования к будущему маршруту, не утверждённая сеть.

При наличии доказанного нарушения status=BLOCKED, даже если есть unresolved.
В остальных случаях любой unresolved исключает ALLOWED.
Passage может выходить за сегмент: такой результат BLOCKED; границы не скрываются.
В sections показываются только части внутри кандидата. Technical nodes не создаются
до формирования итоговой сети.

Основные коды: CLEARANCE, FORBIDDEN_INTERSECTION, CROSSING_ANGLE,
TOUCH_OVERLAP_OR_INCOMPLETE_CROSSING, SPECIAL_PASSAGE_OUTSIDE_SEGMENT,
SPECIAL_CLEARANCE_CONFLICT, UNKNOWN_RESTRICTION, UNKNOWN_EXISTING_DIAMETER.
Полигональный газопровод/кабель проверяется по тем же правилам спецперехода,
что и линейный (угол — у границы полигона в точке входа, приложение п. 42).

400 — некорректный запрос/контекст цели; 404 — импорт отсутствует;
409 — геометрия не подготовлена; 422 — превышение лимита сложности;
503 — недоступно хранилище. API ничего не изменяет в импорте.

## Зафиксированные трактовки

- отступ равен минимальному расстоянию + половине ширины новой пары + половине
  габарита линейной коммуникации (газ 0,40, кабель 0,20, сеть по таблице 1);
- равенство допустимо, численная погрешность 1e-6 м, не инженерный запас;
- касание/совпадение с линией не является специальным пересечением;
- угол на вершине полигона — минимум углов к инцидентным рёбрам (консервативно);
- для линейных road/tram_tracks границы ±3 м от точки пересечения;
- неизвестные дополнительные типы и неизвестный табличный ДУ существующей сети
  возвращают INDETERMINATE, а не положительное решение;
- собственный ОКС определяется пространственно, для MultiPolygon по компонентам;
  исключение действует только на подход к явно выбранной целевой точке, другие
  ограничения остаются активными.

## Неоднозначность специального перехода ±2 м

Технический конфликт: для газа/кабеля буквальные ±2 м специального прохода
короче зоны отступа с учётом габаритов даже при перпендикулярном пересечении.
Буквальная проверка возвращает `SPECIAL_CLEARANCE_CONFLICT`.

По умолчанию действует расширение: специальная зона расширяется с каждой
стороны ровно настолько, чтобы отступ выполнялся за её пределами (требуемое
расстояние / sin угла пересечения; для DN50 через газ — 2,4 м вместо 2,0 м).
Тогда пересечение газопровода, кабеля и тепловой сети большого ДУ становится
допустимым ценой более длинного участка с `Kспец`. Это осознанное решение:
приложение задаёт для этих объектов коэффициент специального прохода, то есть
пересечение предполагается возможным, а отказ от каждого пересечения оставил
бы ОКС за ними неподключёнными (штраф 100 млн ₽ каждый). Буквальное прочтение
включается параметром `-Dlct.extendSpecialZone=false`; вопрос организаторам
остаётся в силе. В ответе сохраняются требуемые интервалы и отдельная причина
отказа.

Разъяснения организаторов (вопросы 3, 6–10) конфликт не снимают. Ближе всего
вопрос 7: «Внутри разрешённого специального пересечения минимальное
горизонтальное расстояние не проверяется» — подтверждает, что внутри зоны
отступ не требуется вовсе (сам конфликт возможен только у её границы), но не
говорит, где именно проходит граница: заданы ли ±2 м буквально или до места,
где отступ уже выполняется. При буквальных ±2 м требование не может сработать
ни при каком ДУ (даже DN50 требует 2,4 м у газопровода против ±2 м зоны) —
буквальное прочтение делает переход через газ/кабель невозможным всегда, что
противоречит наличию для них `Kспец` в таблице 2. Текст разъяснений — в
`docs/sources/clarifications.txt`.

## Пределы API

Один сегмент до 100 км, до 4096 близких компонентов препятствий, до 8192
событий пересечения; превышение отклоняет запрос целиком (422), без усечения
положительного результата. Геометрии препятствий остаются в PostGIS.

## Источники

Нормативные: docs/sources/technical-appendix.txt, разделы 2.2, 3.1, 4;
docs/sources/clarifications.txt, вопросы 3, 6–10. Разъяснения не снимают конфликт ±2 м.
PostGIS: https://postgis.net/docs/ST_LineLocatePoint.html,
https://postgis.net/docs/ST_LineSubstring.html, https://postgis.net/docs/ST_DumpSegments.html.
Расстояния проверяются через ST_Distance, без приблизительной полигональной
аппроксимации буфера. Расчёт пересечений выполняется в БД, большие входные
геометрии не загружаются в Java heap.
