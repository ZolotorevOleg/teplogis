# API итогового GeoJSON

## Сформировать результат

`POST /api/v1/imports/{id}/outputs/geojson`

Тело необязательно. Оно совпадает с запросом расчёта вариантов (`cost-api.md`):

```json
{"targetOrdinals":[3],"maxVariants":1}
```

Без `targetOrdinals` обрабатываются все ОКС. `maxVariants` допускает значения
1–3. Успешный ответ имеет `Content-Type: application/geo+json`, заголовок
`Content-Disposition` с именем `.geojson` и содержит уже проверенный
`FeatureCollection`. Результат строится потоково: по одному варианту записывается
во временный файл и отдаётся с `Content-Length`, целиком в памяти не хранится.
Каждый вариант перед записью полностью проверяется, включая повторную
пространственную проверку каждого прямого участка каждой линии на ограничения
приложения, сверку длины с геометрией и запрет излома специального прохода;
вариант с нарушением не выгружается, ранги назначаются оставшимся. Если ни один
допустимый вариант не построен, возвращается 422.

Заголовки: `X-Variant-Count` — число вариантов, `X-Result-Status` — итог расчёта
(`RANKED`, `PARTIAL`, `INCOMPLETE_SEARCH`). `X-Search-Incomplete-Oks` перечисляет
ОКС, оставленные неподключёнными без доказательства отсутствия маршрута
(поиск остановлен пределом); такой вариант выдаётся только если нет варианта без
сомнительных ОКС. Новая камера, построенная на существующей линии, учитывает её
примыкания (2 в середине линии, 1 в конце) в пределе четырёх и её ДУ в собственном
диаметре. Расход ОКС, равный 0, допустим на любом шаге расчёта.

Свойство `unproven_oks_ids` объекта `variant_summary` — необязательное дополнительное поле (раздел 7, «допускаются и при
проверке обязательной части решения игнорируются»): подмножество `unconnected_oks_ids` ЭТОГО варианта, для которых поиск не
доказал отсутствие маршрута. Оно посчитано отдельно для каждого варианта — в отличие от агрегированного `unprovenOksIds`
ответа `.../link` (объединения по всем выгруженным вариантам сразу), которое годится только для решения «выдавать ли
результат», а не для того, какие точки подсвечивать на карте выбранного варианта.

### Результат ссылкой

`POST /api/v1/imports/{id}/outputs/geojson/link` принимает то же тело, но отвечает небольшим JSON
(`token`, `downloadUrl`, `fileName`, `bytes`, `variantCount`, `status`, `unprovenOksIds`); файл остаётся на сервере час
(не больше шести результатов) и скачивается `GET /api/v1/outputs/{token}/file` напрямую на диск. Интерфейс использует этот
путь: в память страницы читается только результат, который помещается на карту (до 120 МБ), большой сохраняется на диск ссылкой.

Тело запроса может содержать `"mode": "DEPTH"` — дополнительный режим с учётом глубины (см. depth-mode.md): отдельный набор вариантов
(`variant_id` вида `d1`), числовые `depth_start`/`depth_end`, `Kгл` в стоимости. Без `mode` результат двумерный, глубины `null`.

Тело запроса может содержать `"strictCompleteness": true`: тогда результат, в
котором ОКС остался неподключённым только потому, что поиск был неполным, не
выдаётся, а возвращается 422 `SEARCH_INCOMPLETE` со списком ОКС. По умолчанию
(`false`) такой результат выдаётся с пометкой, если нет варианта без сомнений.

## Проверить готовый результат

`POST /api/v1/imports/{id}/outputs/validate`

Тело — проверяемый `FeatureCollection` с `Content-Type: application/geo+json`
или `application/json`. Валидатор сопоставляет ссылки, ОКС и штрафы с исходным
импортом `{id}`.

Если результат рассчитан для выбранных ОКС (`targetOrdinals` в запросе выгрузки), полноту «каждый ОКС подключён или перечислен как неподключённый» нужно проверять только по ним: передайте тот же список параметром `?targetOrdinals=12&targetOrdinals=15`. Без параметра проверяются все ОКС импорта.

Подход к ОКС, разрезанный на несколько линий техническими узлами (например, границами спецперехода газопровода), проверяется как один прямой отрезок, каким его строил планировщик: пока он оканчивается внутри контура своего ОКС, габарит до этого контура на нём не применяется. Все остальные объекты проверяются на каждом куске отдельно.

Успешный ответ:

```json
{
  "valid": true,
  "featureCount": 2,
  "variantCount": 1,
  "networkCount": 1,
  "chamberCount": 0,
  "technicalNodeCount": 0,
  "summaryCount": 1
}
```

Ошибка контракта возвращает HTTP 422:

```json
{"code":"INVALID_OUTPUT_GEOJSON","path":"$.features[1]","message":"score is invalid"}
```
